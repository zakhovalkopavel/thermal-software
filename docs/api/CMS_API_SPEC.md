# CMS API specification

Human-friendly site content, SEO meta, admin auth, and SSR HTML shell.
Scientific datasets remain file-based; this module only stores editorial CMS data in Postgres.

## Entities

| Table | Purpose |
|-------|---------|
| `admin_user` | Single admin password hash |
| `page` | One row per public route (`path` unique) |
| `site_setting` | Key/value (`gaMeasurementId`, `siteName`) |

`page.kind`: `calc` | `hub` | `info` | `standalone`

- `calc` / `hub`: SEO + short `resume` for hub cards (no body required). Calculator under-title intros are **not** taken from `calc` pages.
- `info` (calculator surface): path under `/info/materials/...` or `/info/processes/...`. `resume` ≈ short intro (~300 characters plain text); `bodyHtml` = expandable in-page full info (target ≤2500 characters plain text). Rendered under the calculator title via `SectionIntro` (more / less), not as a separate “About this tool” chapter for ordinary use.
- `info` (overflow details): path containing `/details/` for formula-heavy topics that exceed the inline budget. Overflow pages show a **Back to calculator** control.
- `standalone`: SEO + `resume` + WYSIWYG `bodyHtml` (`/about`, `/overview`).

Property symbols in the short intro are tokenized in the frontend (`PROPERTY_TERMS`); matching headings in `bodyHtml` use `id="prop-…"` anchors.

## Public API (`/api/v1`)

| Method | Path | Description |
|--------|------|-------------|
| GET | `/pages?path=/about` | Published page by path |
| GET | `/pages/list?prefix=/materials` | Published pages under prefix |
| GET | `/site-settings/public` | `gaMeasurementId`, `siteName` |

## Admin API (JWT Bearer)

| Method | Path | Description |
|--------|------|-------------|
| POST | `/admin/auth/login` | `{ password }` → `{ accessToken }` |
| PATCH | `/admin/auth/password` | Change password |
| GET | `/admin/pages` | List all pages |
| POST | `/admin/pages` | Create page |
| PATCH | `/admin/pages?path=/about` | Update page fields |
| GET/PATCH | `/admin/site-settings` | Read/update GA id and site name |

`bodyHtml` is sanitized on write (allowlisted tags/attributes via `HtmlSanitizer`). `id` is allowed so property anchors work.

## First-install admin password

1. Optional `ADMIN_PASSWORD` in `.env` (also generated by `make setup-secrets`)
2. If no `admin_user` row exists on boot: use env password or a random one
3. Password is logged once and written to `tmp/reports/admin/initial-admin-password.txt`
4. Change it in `/admin/password`

## Seed / install

```bash
make db-install
# or: docker compose exec backend npm run db:install
```

Upserts from:

- `shared/seed/cms/pages.json` — hubs, calc SEO, 14 in-page calculator-info shells, ~26 overflow detail shells
- `shared/seed/cms/site-settings.json`

Also deletes retired seed paths listed in `RETIRED_CMS_PATHS` (e.g. former combined `/info/materials/gases`).

Migrations run on backend boot (`migrationsRun: true`) and again from `db-install`.

## Frontend routes

- Calculators: `/materials/*`, `/processes/*` — `SectionIntro` loads the matching `/info/...` page inline.
- Overflow / standalone: `/info/materials/*`, `/info/processes/*`, `/about`, `/overview` — `CmsContentPage` (overflow shows back link).

## SSR shell

`GET /ssr` and `GET /ssr/*` (excluded from `/api/v1` prefix) render an HTML document with:

- `<title>`, description, keywords, OG, canonical from the matching `page`
- optional `#ssr-content` with `bodyHtml`
- `#page-bootstrap` JSON for the SPA
- gtag when `gaMeasurementId` is set
- Vite client scripts (dev) or hashed assets (production)

Nginx document routes rewrite to `/ssr/...`; `/src`, `/@vite`, `/assets`, etc. stay on the frontend.
